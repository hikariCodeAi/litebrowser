# LiteBrowser 性能报告

更新日期：2026-10-24。

LiteBrowser 是基于 Chromium 的精简浏览器，专注内存优化。本报告区分已归档的历史测试与当前发行版本的验证状态。

## 历史 Linux 受控测试

测试日期：2026-10-14（北京时间）。环境为 Ubuntu 22.04、Linux 6.8、x86_64、48逻辑线程和约64GiB内存，以非root账号和浏览器沙箱运行，通过cgroup v2记录物理内存。

比较对象为相同Chromium 155.0.8059.39内核的原始基线与LiteBrowser八层优化候选版。下表是一次已归档的100循环合成负载测试记录；每循环分配TypedArray缓冲并生成、释放Blob，总计处理约500MB数据。它是用于观察内存行为的合成测试，不是完整视频编码、真实业务导出或日常浏览的性能结论。

| 记录指标 | 原始基线 | LiteBrowser历史候选版 |
| --- | ---: | ---: |
| 时间加权平均物理内存 | 765.73 MiB | 309.45 MiB |
| 记录到的物理内存峰值 | 1014.02 MiB | 397.84 MiB |
| 结束空闲内存减去初始空闲内存 | +592.92 MiB | -8.15 MiB |
| 测试总耗时 | 78.30秒 | 78.14秒 |
| 完成循环数 | 100 | 100 |

上述记录中平均内存下降约59.59%，峰值下降约60.77%。这些数值只描述该次Linux合成负载，不能据此保证Mac版、Windows版、任意网站或真实生产业务具有相同收益；单次负差值也不能证明不存在所有类型的内存泄漏。

另有历史Web平台确定性检查记录：两份Linux构建均完成31项导航、脚本、网络、布局、图片、媒体等检查，记录中未发现用例间的功能回归。这些检查覆盖有限，不能替代完整网站兼容性验证。

## 版本与结果的对应关系

上述历史Linux候选版先于当前品牌、授权和静默更新功能的后续改动。当前Mac版或Linux 1.0.0预览版完成构建或基础功能检查，不代表它们已完成同等性能测试。Linux版本暂通过发布仓库手动更新。后续结果将分别注明平台、浏览器版本、测试方法与测量范围。

下载与版本说明请见[LiteBrowser Releases](https://github.com/hikariCodeAi/litebrowser/releases)。


## 主页曲线与公开采样数据

[下载公开采样数据 JSON](../assets/benchmark-data.json)。该文件仅保留泛化环境、测试对象、负载规格、单位、摘要与绘图样本，不包含主机、账号、路径或绝对时间戳。

主页 Fig. 02「物理内存采样」使用 B3 与 L（历史八层候选）各自的全部 78 个 cgroup v2 `memory.current` 采样点。横轴为该组单调时钟减去本组首点后的相对秒数，纵轴为字节数除以 1,048,576 得到的 MiB。每组首点为实际记录的 0 MiB；该零点原样保留，不代表浏览器运行占用为零。折线仅依采样顺序连接，不平滑、不剔除零值或异常值，曲线不是 `memory.peak`。

Fig. 03「批次结束空闲内存」使用每组全部 10 个批次空闲采样，横轴仅为实际完成的周期 10、20、…、100，纵轴同样为 `memory.current` 的 MiB 值；不添加 cycle 0。每批 10 周期后自然空闲约 5 秒取样。初始空闲约 10 秒，全部任务结束后自然空闲约 15 秒，连续采样目标间隔为 1 秒；实际相对时间以 JSON 为准。

负载每周期分配 10 个 512 KiB TypedArray 缓冲并创建、释放 Blob，100 周期累计分配 524,288,000 字节（500 MiB）。Blob 的类型标记不意味着进行了视频编码；这不是完整视频导出、真实 Create 业务或日常网站测试。既有表格的“约500MB”是概述，字节规格以此处和 JSON 为准。

JSON 摘要中的 start/end 为初始与末尾自然空闲期均值，avg 为时间加权物理内存均值，peak 为记录的物理峰值，delta 为 end 减 start；摘要保留归档报告的两位 MiB 精度。两组总耗时分别为 78.302 秒与 78.135 秒。图表旁标注“历史 Linux 实测 · 2026-10-14”，日期采用北京时间；历史八层候选结果不作为当前 Linux 1.0.0/build 1 或 macOS 预览版的性能结论。
